究极手，是怎么把东西粘住的

任天堂在 GDC 2024 讲了王国之泪物理系统的“铁律”，却从没公开过究极手本身的代码。所以我们不抄代码，只照规则重做一遍：抓、转、找点、粘、整坨搬、动力，六步，每一步只多做一件事，每一步都能在「亲手试试」里开关对比。官方

本页是原创教学原型，只讲方法，伪代码每段不超过 8 行。点赞、收藏、关注后，作者会私信发送地址。可信度标签：官方 GDC 讲座/官方采访，媒体 媒体转述，社区 玩家实测/Wiki，推测 我们自己的推断或未核实。GDC 原视频本轮没能直接核对，讲座内容来自 Famitsu 等媒体对幻灯片和发言的转述。

任天堂的铁律

  • 引擎分三层：Havok 物理中间件，之上是任天堂自研物理库，再往上是王国之泪专用层。官方媒体（Havok 一词以 Famitsu 幻灯片图文为准，待看视频确认）
  • 核心规则：世界里所有物体都由动力学刚体 + 约束构成，无一例外。官方
  • 被禁用的是运动学刚体（按动画强行移动）：它实现简单，但质量无穷大，会让物理计算崩坏。官方
  • 例子：早期神庙闸门是动画驱动的，玩家用究极手塞进一块冰，闸门直接把冰压进地面并高速抖动；改成物理驱动后，冰块能把闸门顶住、留出缝隙，反而衍生出新解法。官方
  • 倒转乾坤（Recall）也一样：初版倒转回来的石块会把马车撞碎，改成物理驱动后和马车按同一套规则计算。官方
  • “没有车辆程序”：车、门、桨船都由轮子、木板、链条等部件各按物理规则凑出来。官方一个轮胎由 wheel / motor / shaft 三个刚体组成，轴不直接连车轮，而是支撑马达，并带悬挂。官方
  • 设计哲学：“不是做有趣的东西，而是做让有趣的事情发生的系统”。官方

这条铁律就是我们的第一条规则：连你手里拿着的东西，也不能例外。

六步实现

01抓：给速度，别改坐标

从屏幕中心打射线，记下命中点（零件局部坐标）；每帧用“目标位置 − 当前位置”乘系数得到速度，交给物理引擎。朝向存成相对玩家偏航角的值，所以转身时东西跟着转。

为什么：直接改坐标就是运动学老路，会穿墙，也会把别的零件挤飞。官方只说物理驱动用速度/加速度控制，“用速度驱动抓取”是我们按铁律做的推断。推测

grabLocal = body.toLocal(hit.point)
each frame:
  target = camera.pos + camera.dir * holdDist + yawRot * relOffset
  anchor = body.toWorld(grabLocal)
  v = clamp((target - anchor) * gain, maxSpeed)
  body.setLinvel(v)        // 不 setTranslation
  body.setAngvel(orientErr * gain)

试试：关掉「L0 瞬移（会穿墙）」是默认的速度驱动；打开它，抓着的木板会穿过墙。

02转：45° 一格并吸附

每按一次旋转键转 45°，然后把朝向吸附到最近的网格角度，木板才摆得正。游戏里具体怎么吸附任天堂没讲，45° 是我们自己的设计选择。推测（游戏里按住 R 配合方向键旋转，来自社区指南，步进角度未确认。社区）

onRotateKey(axis):
  relRot = rotate(axis, 45deg) * relRot
  if snapRotate:
    relRot = snapToGrid(relRot, 45deg)  // 四元数吸到最近网格

试试：「L2 45° 吸附」开关。关掉后旋转是连续的，很难摆正。

03找点：问引擎“最近的两点”

举着的时候，每帧让“这一坨零件”的碰撞体和别的零件的碰撞体互相求最近点，距离小于阈值就画预览线。物理引擎自带这个查询（Rapier 的 contactCollider 返回最近点对和距离），不用自己写几何。

媒体报道过一件任天堂专利：粘合时在两个物体上同时显示吸附点。媒体（我们没能确认专利编号与权利要求，待核实）

best = null
for a in held.colliders:
  for b in others.colliders:
    c = a.contactCollider(b, threshold)
    if c and (!best or c.dist < best.dist): best = c
preview = best   // 两个最近点 + 距离

试试：「L3 找粘接点」开关，换个角度最近点就会跳。

04粘：先贴合，再连接

松手时先把整个被抓的装配体平移“最近点之间的间隙”，让两点贴上，再把两个零件在粘合图里连一条边。这条边怎么实现，是本作最关键的选择，见下文三种模式对比。

内部表示是我们的猜测：粘出来的车会晃、会被扯开，行为更像关节，但任天堂从未确认粘合体内部是关节还是合并刚体。推测另外，粘在一起的零件之间要关掉碰撞，否则会互相顶着打架（用接触过滤钩子实现）。

release():
  gap = best.pointB - best.pointA
  assembly.translate(gap)
  glue.addEdge(partA, partB)
  realize(mode)       // joint / merge / besiege
  contactFilter: same assembly => no collision

试试：「模式」三个按钮（关节 / 合并 / 围攻式），搭一座木板桥再砸一块石头。

05整坨搬：每个零件追同一个变换

粘完再抓，抓的是一整个装配体。如果只驱动被抓的那一块，其余全靠关节拖着走，长了就软塌塌。所以让装配体里每个零件都按同一个刚体变换去追目标，关节几乎不用出力。

上限：玩家实测一次最多粘 21 个零件，Zelda Wiki 采用该数；这不是官方公布的规格，原因未知。社区我们的原型沿用 21。零件越多，要同时解的约束越多，所以稳定性和求解器迭代次数有关。

driveAll:
  T = rigidTransformToward(target)   // 一个整体位姿误差
  for p in assembly.parts:
    p.setLinvel(velocityOf(T, p.pos))
    p.setAngvel(T.angular)

试试：「L5 整坨一起搬」开关；再把「求解器迭代次数」拉到 1，同一根长杆会变面条，拉到 8 才站得直。游戏的求解器参数没有任何公开来源，我们不做对应。推测

06动力：风扇是力，轮子是铰链

风扇最简单：每帧在它的位置、沿局部 +Z 方向施加推力（addForceAtPoint）；热气球同理，施加向上的升力。轮子要能转，所以不能合并，也不能用固定关节：用两个球关节凑成一条铰链轴，再给轮子和车身施加大小相等、方向相反的马达扭矩。官方讲过轮胎是三刚体加悬挂；风扇、火箭、转向杆怎么施力，官方没讲，下面是我们自己的做法。推测

fan.update():
  body.addForceAtPoint(localZ * thrust, fan.pos)
wheel.update():
  hinge = sphericalJoint(axisA) + sphericalJoint(axisB)
  wheel.addTorque( axis * motor)
  chassis.addTorque(-axis * motor)   // 等大反向

试试：这一步没有开关，直接在亲手试试里放轮子和风扇，装上去就跑。没有一行“车辆程序”。

关节 vs 合并 vs 围攻式

维度关节合并围攻式
怎么连每块一个刚体，中间加固定关节多个碰撞体挂到同一个刚体上关节 + 受力检查
稳定性受迭代次数影响，会弯、会晃、长了会软铁板一块，最稳同关节，但超载就断
成本刚体和约束都多，数量越多越贵最便宜，只有一个刚体多一次每帧受力估算
怎么拆开删掉关节即可要把碰撞体拆回新刚体，重算质量和惯性删关节，或超载自动断开
转动部件可以：改用转动关节不行，合并后无法单独转可以
更像哪个游戏像王国之泪的手感推测无对应推测像围攻社区

围攻式的断裂检查：每帧估算关节被拉开的距离 × 零件质量 × 系数 k，连续 4 帧超过阈值就断开。这是我们的简化，不是围攻的实际算法。推测
